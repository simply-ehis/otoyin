# docs/reports/ — Header Convention

Every report in this directory carries a machine-parseable header block within
its first 10 lines, so a staleness sweep is a mechanical check instead of a
re-read of 20 documents.

## Required header block

```markdown
**Date:** YYYY-MM-DD            — when the report was written
**Prompt:** <path>              — optional; the prompt-library item that produced it
**Status:** <TOKEN> [ — prose]  — closed vocabulary, see below
**Last verified:** YYYY-MM-DD   — date the Status was last confirmed against the tree
**Superseded by:** <path>       — required when Status is SUPERSEDED
```

`Last verified` is the load-bearing field: a report can be *written* in March
and *still true* — the sweep cares about when someone last checked. Keep the
prose after the Status token to one short clause; details belong in the body.

## Status vocabulary (closed set)

| Token | Meaning | Sweep treatment |
|---|---|---|
| `PLANNED` | decision/plan recorded, work not started or not adopted | needs periodic re-verification |
| `IN PROGRESS` | work ongoing; doc is a live reference | needs periodic re-verification |
| `DONE` | work/audit complete and claims currently true | needs periodic re-verification |
| `SUPERSEDED` | another doc replaces this one | body frozen; follow the pointer |
| `HISTORICAL` | point-in-time snapshot; body describes what was true at `Date` | exempt — never updated, never trusted as live guidance |
| `GENERATED` | regenerated by a script | sweep = re-run the generator, never hand-edit |

Freeze rules: `HISTORICAL` and `GENERATED` files set `Last verified` to their
`Date` (frozen) and are exempt from age checks. `SUPERSEDED` must name its
successor.

## Mechanical sweep

```bash
python scripts/check-report-headers.py          # fails on missing/malformed headers
python scripts/check-report-headers.py --stale  # also warns when Last verified > 30d old
```

The script scans `docs/reports/*.md` and `*.txt`, skipping `README.md` (this
file) and `LOOP_STATUS.md` (the dashboard itself — its per-row table *is* the
status). It is wired into the pre-commit gate; when you add a report, add the
header block in the same commit.

## Writing a new report

1. Copy the header block above; pick one Status token.
2. If the report records a snapshot you never intend to update, use
   `HISTORICAL` and say so — that is what keeps sweeps cheap.
3. If you re-verify an old report's claims, update its `Last verified` (and its
   `Status` if reality changed) instead of writing a new report when the change
   is small; write a new dated report when it is not, and mark the old one
   `SUPERSEDED`.
